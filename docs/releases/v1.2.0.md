# ResolveOps v1.2.0 — Workflow lifecycle repair

Customer complaints now start from unconfirmed intake, read scoped financial evidence, pause for
separate approval and remain open during refund submission. Only a final settlement event and a
fresh read can resolve the relevant issue. Failed or cancelled refunds require a newly approved
replacement; idempotency, late events and historical attempts remain safe.

Employee requests bind the actual requester and manager. The sandbox explicitly simulates these
roles. Identity, MFA, policy and existing-access checks precede a verified synthetic grant.

## Live AI evidence

30 trials were requested. One passed, the second stopped on free-provider quota, and 28 were
not attempted. The passing integrated trial used 13 model calls and seven application-tool reads
in 29.17 seconds, with 40,796 input and 4,603 output tokens. It resolved the targeted synthetic
duplicate-charge issue after simulated approval and settlement; the other issue stayed open.

Full-batch usage and cost remain unknown. The attached raw report and per-role summary preserve
the failed attempt. This is not a 30-trial reliability result. Evaluated core `466a22f` has the same
`src/` and `scripts/` Git content as release commit `020ef9d`.
